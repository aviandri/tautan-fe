## Findings

Severity: **High** = visitors can't read or use something; **Medium** = wrong content or lost work for the owner; **Low** = polish.

### 1. High: dark themes make the inner tiles of several cards unreadable (light text on light-grey tiles)

- **Steps:** log in as `heavy_all@example.com`, Design → Malam (or Arang) → Save design, open `/heavy_all` on a phone.
- **Expected:** every text in the card meets contrast. Inner tiles stay dark like the card, or use dark text.
- **Actual:** the inner tiles render as light grey (~`rgb(176,184,185)`) while the text stays the theme's light ink (`#f3ead8` in Malam, `#f2f0eb` in Arang). Measured contrast is **1.7–1.8:1**; WCAG AA needs 4.5:1. The automated scan found **44 such texts per dark theme** on `/heavy_all`, and 0 for the same cards in the light themes. Affected cards:
  - **Shop** grid items (name, price)
  - **Marketplace** rows (Shopee / Tokopedia / TikTok Shop)
  - **WhatsApp order** item rows and the name/address inputs (placeholder text is almost invisible)
  - **Media kit** platform tiles
  - **Rate card** rows
  - **Events** schedule rows
  - **Podcast** episode rows

  Top-level card surfaces, link buttons, FAQ, testimonials and forms are fine in both dark themes (`f01-malam-top-ok.png`).
- **Screenshots:** `f01-malam-shop-marketplace-order.png`, `f01-arang-shop-marketplace-order.png`
- **Likely cause:** a light "inner surface" token isn't redefined for dark palettes.

### 2. High: in all 6 light themes, the gate unlock buttons are invisible

- **Steps:** add a gated card of each kind (password, email, age_18, follow), pick Kertas / Sawah / Senja / Laut / Kunyit / Batu, open the public page.
- **Expected:** "Unlock", "I'm 18 or older" and "I followed, unlock" look like buttons, like "Enter" on the giveaway card right above them.
- **Actual:** the button background is computed as **exactly the card's surface colour**, so it's indistinguishable from the card. The 2px border also doesn't show. The 18+ and follow gates look like a heading and a plain line of text with no obvious action. Malam and Arang render them correctly (filled accent).
- **Screenshots:** `f02-kertas-gates.png`, `f02-senja-gates.png`; for comparison `f02-malam-gates-ok.png`
- **Likely cause:** the gate submit button uses the "cycle" surface token instead of the accent.

### 3. Medium: onboarding's starter sections publish placeholder copy to visitors

- **Steps:** sign up → "Selling things" → keep the default ticks (Shop heading, Testimonials, Email signup, FAQ) → finish with "Publish now" on (the default).
- **Expected:** the visitor never sees owner instructions. Empty starters are either hidden on the public page until edited, or created as drafts.
- **Actual:** placeholder content is **saved as real block data** and rendered publicly:
  - Testimonial: *"What customers say about you goes here. Replace it with a real quote." — Customer name*
  - FAQ: *"Add your first question"* with the answer *"Replace this with your answer. Tap the FAQ card in the editor to change or add questions."*

  The public API returns these strings in `blocks[].data`. On a page published straight from onboarding, they are the first things a visitor sees under the header. Source: `src/lib/onboarding/starters.ts`.
- **Screenshots:** `f03-public-placeholder-testimonial-faq.png`, `f03-editor-after-onboarding.png`

### 4. Medium: Design page loses unsaved changes on navigation, with no warning

- **Steps:** Design → click a different theme (the bar shows "N unsaved changes · Discard · Save design") → click **Page** in the top nav.
- **Expected:** a confirm ("Discard unsaved changes?"), or auto-save.
- **Actual:** navigates immediately. No `beforeunload` or in-app prompt fired. Returning to Design shows the old theme, so the changes are gone. The Page editor next to it saves changes immediately ("Changes are live as they save"), so owners will reasonably expect the same on Design.
- **Screenshots:** `f04-design-unsaved-bar.png` → `f04-after-nav-changes-lost.png`

### 5. Medium: poll "one vote per day" blocks different people on the same network and browser

- **Steps:** visitor A votes on a poll. Visitor B, a fresh browser profile (no shared cookies or storage) on the same Wi-Fi with the same iPhone Safari version, opens the page and votes.
- **Expected:** B can vote.
- **Actual:** B still sees the Vote button. On submit, the API returns **409 `already_voted`** and the card shows "You already voted today". The dedupe key is `visitorHash(profile, IP, User-Agent)` per day (`tautan-be/internal/server/engage.go:255`). In Indonesia, many mobile users share carrier-NAT IPs and have identical iOS Safari UAs, so real voters will be silently refused. Also, a visitor who *has* voted is shown the Vote button again after a reload, and only learns otherwise after submitting.
- **Screenshot:** `f05-poll-new-visitor-already-voted.png`
- **Suggestion:** combine the hash with a first-party cookie or localStorage id, and render the voted state on load.

### 6. Low: "Choose a look" has no default selection, and skipping it saves a theme that isn't one of the 8

- **Steps:** onboarding → Look step → press Continue without picking a tile.
- **Expected:** one tile pre-selected (e.g. Kertas), or Continue disabled until a pick.
- **Actual:** no tile is selected and Continue works. The profile is saved with `theme.preset = "classic"`, a grey look that matches none of the 8 tiles. On the Design page no preset shows as selected.
- **Screenshot:** `f06-choose-a-look-nothing-selected.png`

- **Screenshots:** `f07-desktop-arang-grey-slabs.png` vs `f07-desktop-kertas-for-comparison.png`
